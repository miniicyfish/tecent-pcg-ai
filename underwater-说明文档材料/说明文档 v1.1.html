目录与摘要

剧播完后，用户的延展兴趣（搜解析、补考据、复看名场面）几乎全部流向站外。腾讯视频承担核心内容投入且拥有官方资源，却缺少一个承接剧后内容消费的站内产品形态。

《庆余年 · 水下》补的就是这一层：当用户想更深入理解一部剧、探索更多面的叙事时，可以以“原住民”的身份进入官方叙事构筑的世界。主线剧情不被改写，但观看视角可以改变；同一段剧情再次上演，用户能通过四种 AI 驱动的交互方式，发现正剧镜头之下被覆盖的故事。

它不是聊天工具，也不是互动小说，而是一套可复用的长视频衍生 AI 交互框架：AI 基于官方资源与当前语境判断“此刻能否看见更深一层”，为每次探索生成不可预写、但仍然还原且深刻的内容。核心机制与 IP 内容解耦，换一套 IP 内容包，就能生成另一个世界。

PROLOGUE · 序章

一个判断

赛题问的是：AI 原生时代"看内容"这件事的终极形态。我们的判断是——AI 给长视频带来的不是"更多自由度"，而是"更多纵深"。

每一部剧都是一座冰山。观众看到的是水面以上——剧本写好的台词、镜头拍下的画面、剪辑保留的镜头。水线之下还有一整座山——角色没说出口的潜台词、没被拍到的日常侧面、没被展开的世界细节、主线之外的边缘故事。这些在编剧脑子里存在过，受限于时长和镜头语言，最终没能浮上水面。

设计原命题

AI 不改变一部剧讲了什么。AI 让观众有能力往水下看。

基于这个判断，我们做了《庆余年 · 水下》——一个腾讯视频长视频 IP 的 AI 衍生交互层。看完剧，用一个小人物的视角"活"一遍那些镜头没拍到的故事。固定的是世界（主线由原作锁定），自由的是你的眼睛（你选择往哪里看得更深）。

MODULE ONE · USER INSIGHT

用户洞察与问题定义

1.1 目标用户

腾讯视频拥有大规模付费会员基础。在这个用户池里，《庆余年 · 水下》优先服务的不是"随便点开一集当背景音"的泛用户，而是三类对 IP 有更高情感投入、更强分享意愿、更明显延展消费需求的人。

用户类型典型行为当前缺口产品机会
分享型年轻观众 追剧时刷微博、小红书、朋友圈，喜欢发截图、金句、人物 cut 分享素材多来自站外，腾讯视频只承担播放入口 用个性化结语和分享卡片，把"我在这个世界里的经历"变成可传播内容
深度 IP 粉丝 看解析、补原著、做考据、复看名场面，关注角色潜台词和世界观细节 深度消费发生在豆瓣、B 站、小红书等站外社区 用 AI 生成镜头之外的纵深，让站内承接"看懂更多"的需求
剧荒回访用户 没有新剧追时，回到喜欢的老 IP 重刷片段或搜二创 回访路径零散，缺少新的官方体验入口 用小人物视角和多身份线，让老 IP 在剧荒期仍有新的消费理由

这三类用户未必占会员的大多数，但他们贡献了更高的停留、复看、讨论和传播价值。他们也是腾讯视频最不应该流失、却最容易被站外社区承接走的用户。

1.2 用户洞察 · 用户想要的不是自由度，是纵深

在定义产品方向之前，我们先排除了三种看似合理但方向错误的思路。

分支选择叙事 — 把看剧变成做题

Netflix 的 Bandersnatch 和互动影游把"交互"理解为不断选择路径。但观众看剧的核心状态是连续沉浸，频繁选择会把用户从"观看者"变成"路径判断者"。

让用户写prompt — 大多数观众不想当编剧

Fable 的 AI Showrunner 让用户写 prompt 生成新剧情。它验证了用户对"在喜欢的世界观里看到新内容"有真实欲望；但也暴露了：写 prompt、设定目标、决定人物命运，本质是创作，不是消费。

把长视频变成别的媒介 — 用别的形态替代长视频本身

有人把长视频做得更短（解说）、更刺激（游戏化）、更高自由度（开放世界）。但长视频真正不可替代的优势恰恰是连续叙事、角色厚度和情绪沉浸。AI 应该放大这种纵深，而不是替代它。

排除这三条路后，核心洞察浮出水面：

洞察用户现象产品机会
看完不等于消费结束用户看完正片后继续搜解析、看二创、补原著、读考据剧后消费应该被腾讯视频站内承接
用户想探索，不想改写观众想"再多看看这个世界"，而不是"我来决定接下来发生什么"交互应从"改写剧情"转向"探索纵深"
IP 长尾正在外溢讨论、二创、复看、角色解读主要沉淀在站外平台腾讯视频需要一个官方、个性化、可分享的 IP 衍生层

MODULE 01 · 用户洞察与问题定义

1.3 双向痛点 · 同一件事的两面

这里是这个产品的核心立论。我们不只是在解决用户的体验问题，更是在解决长视频商业模式中的一块结构性缺失。

这意味着：

  • 平台投入的内容成本只能在播出窗口内变现
  • 围绕一部 IP 自然形成的社交势能与平台无关
  • 用户对 IP 的情感深化、复看欲望、"住进世界观"的需求，没有任何站内出口可以承接
  • 赛题原题里反复提到的"出圈"——出圈的目的地几乎都是别的平台

这不是体验优化能解决的问题。这是长视频商业模式中缺失的一块产品——专门用来在剧播完后的长尾期，把延展性消费需求承接在站内的产品形态。

立论

《庆余年 · 水下》就是为这一块缺失而设计的。

1.4 三个使用场景

SCENE 01 · 意犹未尽
刚刷完，不想离开

用户刚看完《庆余年第二季》最新一集，关键剧情刚发生，下一集要等一周。播放页底部出现入口——「进入庆余年 · 水下」。她在 App 内完成了一段新的沉浸体验。原本属于豆瓣的剧后消费，留在腾讯视频。

SCENE 02 · 剧荒回访
回到喜欢的世界

用户最近没有新剧追，习惯性滑首页，没有想看的就关掉去刷抖音。但他想起——"水下"里他还没玩过鉴查院文书的视角。这是衍生层对会员留存最直接的价值——它让 IP 在剧荒期依然能产生消费。

SCENE 03 · 反向激活
被朋友带入

朋友圈出现一张水下分享卡：「我在范府当杂役，今晚月色很好，范少爷站在院子里很久没说话——我看到了和电视里完全不一样的他」。她没看过《庆余年》，但搜了，从第一集开始看。衍生体验反向把新用户带回了主内容。

这三个场景共同勾勒出这个产品对腾讯视频的真实价值：它把"剧播完之后"的所有用户行为路径，从站外拉回到了站内。

MODULE TWO · PRODUCT DESIGN

产品方案设计

2.1 产品概述

《庆余年 · 水下》可以理解为腾讯视频正片之后的官方剧后体验入口。用户看完剧、还想继续理解人物和事件时，不需要跳去站外搜解析，而是直接进入一个由原作世界观搭建的互动空间：换成一个小人物身份，重新经过主线事件，看到镜头没有展开的另一面。

用户不是来改剧情的，而是来换一个位置看剧情。主线不变，但看见的细节、理解到的关系、最后带走的感受会变。

产品边界含义
主线固定范闲会经历什么、刺杀会不会发生、人物命运如何，都由原作决定，用户不能改写。
体验像看剧，不像做题大多数时候系统自动播放剧情；用户只在想“这里还能不能看深一点”时主动使用 AI 交互。
选择改变视角用户选择的不是“接下来发生什么”，而是“我站在哪里、用什么方式观察这件事”。

2.2 五项核心机制

机制一 · 小人物身份选择

进入体验的第一步，是选择一个不在主线中心、但能碰到主线余波的小人物身份。比如茶馆掌柜听见街面上的风声，鉴查院文书看到机构内部的反应，范府杂役靠近主角的日常生活。身份决定你能自然看见什么，也决定 AI 不能让你知道什么。

所以身份不是装饰性的角色卡，而是产品的“信息权限”。同一件事，茶馆掌柜只能听见市井传闻，鉴查院文书只能看见案牍和命令，范府杂役只能靠近府里的日常细节。这个边界让 AI 生成更可信，不会变成全知全能的剧透。

— 06 —
MODULE 02 · 产品方案设计

机制二 · 视觉小说式主线播放

用户选好身份后，体验会像视觉小说一样自动推进。每一幕都由固定剧情节点组成，系统按节奏播放镜头、人物对白和“你”的感知，让用户先像看剧一样进入场景，而不是一上来就被要求做选择。

[镜头 / 旁白]   →   [角色对话 × N]   →   [你的感知]   →   (可选) [水下回响]

机制三 · 四把手电筒：AI 自主判断纵深

当用户觉得某个瞬间“好像还有东西没说完”，可以使用底部的四种 AI 交互方式。它们不是固定彩蛋按钮：同一个工具在不同身份、不同场景下可能有发现，也可能什么都没有。AI 的任务是判断此刻是否真的存在可被这个身份看见的水下信息。

工具响应表现
有发现时生成一小段嵌在当前场景里的补充戏：可能是更细的动作、被压低的对话、某个角色没说出口的念头。
没有发现时给出自然的空结果，告诉用户这个角度暂时看不到更多，而不是为了显得聪明硬编内容。
关键设计：默认是"没有发现"

我们刻意让“没有发现”成为正常结果。这样每一次真的看见水下，才会有分量；同时也能守住小人物身份的可信边界，避免 AI 把用户变成上帝视角。

MODULE 02 · 产品方案设计

机制四 · 水下回响：发现会持续渗透

用户前面发现的内容不会看完就消失。系统会把它记录下来，并在下一幕以“水下回响”的方式回到主线里。也就是说，用户刚才多看见的一层，会改变下一幕的理解方式。

「方才『侧耳』照见的细节，让此刻多了一层意味……」

这让 AI 生成不只是一次性的补充说明，而是会进入叙事记忆。同一段对话，没发现过线索的人只是在看剧情；发现过线索的人会意识到，这句话背后还有另一层关系。

机制五 · 结语生成、分享卡片与旅程回看

一条身份线结束后，系统会根据用户走过的场景和看到过的水下内容，生成一段个人结语、一个分享卡片和一组旅程回看。用户带走的不是通用成就页，而是“我在这个世界里经历过什么”。

2.3 一条实际玩法 · 茶馆掌柜怎么看见牛栏街刺杀

如果用户换成鉴查院文书，同一场牛栏街刺杀会变成另一种体验：茶馆掌柜看到的是街面突然混乱，文书看到的是鉴查院内部骤然紧张。事件没有变，用户站的位置变了，水下也就变了。

MODULE 02 · 产品方案设计

2.4 与现有方案的差异化

赛题方向"AI 交互叙事"看似宽泛，但市场上其实只有几条主流路径。我们对它们逐一做过排除，并最终找到了一个没有人占据的位置。

现有方案 代表 用户身份 主线由谁决定 AI 的角色 我们的判断
分支选择叙事 Bandersnatch · 橙光 · 互动影游 决策者 用户选项 路由（在预写分支间切换） 把观众变成产品经理
AI 角色对话 Character.AI 对话发起者 不存在主线 扮演角色应答 角色脱离故事语境
用户写 prompt 生成新剧情 Fable Showrunner 编剧 用户 prompt 内容生成器 大多数观众不想当编剧
站外二创承接 豆瓣 · 小红书 · B 站 阅读者 不存在主线 不参与 内容静态、不在站内、不个性化
《庆余年 · 水下》 本作品 居民 / 观察者 原作锁定 纵深判断者 + 实时生成者 站内、个性化、即时、官方

这五条同时成立，构成了一个目前还没有被占据的产品位置。它和市场上每一种"AI + 内容"的方案都有清晰的边界：

  • 不和 Bandersnatch 比"分支多不多"——我们根本不做分支
  • 不和 Character.AI 比"角色像不像"——我们的角色生活在故事里，用户不需要去找他们
  • 不和 Showrunner 比"生成质量"——我们不让用户当编剧
  • 不和豆瓣 / B 站比"二创丰富"——我们提供的是个性化、即时、官方的延展层
差异化的真正用途

这种差异化不是为了好看的对比图，而是为了让这个产品的设计意图被严格守住——我们不是在叠加一个"看起来像 AI 的功能"，而是在做一个有清晰边界、有产品观点的衍生层。

MODULE THREE · AI NATIVE

AI 原生能力说明

这个模块是这份文档里我们最希望评委逐字阅读的部分。AI 在这个产品里不是装饰，不是宣传词，不是在已有产品上叠加的"智能小工具"——这个产品离开 AI 不可能存在。

3.1 五项 AI 核心能力

CAPABILITY 01
跨域叙事结构理解

每一次工具调用前，AI 整合：世界观规则 / 8 个核心角色档案 / 用户身份与权限边界 / 当前场景全文 / 之前的场景摘要 / 解锁过的纵深 / 此刻工具的语义边界。这是一个多源叙事上下文的整合任务。

CAPABILITY 02 · CORE
纵深存在性判断 (hasDepth)

这是产品最关键、最非常规的 AI 能力——默认不生成内容。AI 必须先回答二元问题：当前身份 × 当前场景 × 当前工具，是否存在自然、合理、不越权的水下信息？

CAPABILITY 03
上下文敏感的纵深生成

当 hasDepth=true 时，AI 生成的不是抽象解析，而是用户可以直接体验的纵深内容——第二人称感官、贴合世界观、考虑用户之前的发现，让线索之间能自然呼应。

CAPABILITY 04
纵深内容的叙事化组织

AI 还要判断这段内容应该以什么叙事方式浮出水面：哪些通过环境出现、哪些通过角色台词出现、哪些通过小人物的迟疑出现、哪些只能点到为止。

CAPABILITY 05
个性化结语合成与分享素材组织

用户走完一条身份线后，AI 综合所有场景 + 解锁的所有纵深，量身合成一段结语 + 一句分享文案。每个用户的水下经历都不同，所以每个人的结语都不同。这把"个性化体验"延伸到了产品出口——分享卡片本身成为可传播的微叙事。

3.2 hasDepth 的三个允许条件

只有同时满足三个条件，AI 才允许 hasDepth=true，否则必须返回一段自然贴合当前场景的"没有发现"：

CONDITION 01
触发物存在

当前场景文本中存在明确的触发物——不是 AI 凭空想象的。

CONDITION 02
工具语义匹配

用户选择的工具能自然触达这个触发物（侧耳→低语 · 细看→细节 · 追忆→前因 · 跟随→行动）。

CONDITION 03
身份权限合理

用户的小人物身份有权限看见或听见这个信息——茶馆掌柜不会知道皇宫密事。

这个能力的本质

让 AI 学会克制——不是每次都要生成精彩内容，而是在没有可挖之处时承认没有可挖之处。这是这个产品和市面上"无论什么输入都给丰富输出"的 AI 应用最根本的区别。

MODULE 03 · AI 原生能力说明

3.3 离开 AI 还能成立吗？正面回答

赛题模板里有一个关键评分项："去掉 AI 这个产品还能成立吗？" 我们对这个问题做正面回答。

思想实验 · 假设我们不用 AI，预先写完所有内容

试着算一下纵深内容的枚举规模：

枚举维度组合数问题
单部剧 / 单事件 / 工具点 3 身份 × 7 节点 × 4 工具 = 84 看似可控
叠加历史路径依赖（K 个版本） 84 × K（K 取决于已解锁路径数） 每个工具点要写多个版本
单 IP 多事件 每个关键事件都要重复一轮 工作量线性膨胀
整个 IP 库迁移 × IP 数 × 平均事件数 不可维护

但这还不是最关键的。最关键的是——即使我们真的写完了，体验依然会失败。

没有 AI，会失去的四件事

失去的能力为什么
① 自然空结果 大部分工具点回应"没有发现"。如果是预写的固定字符串，用户用一两次就识破。AI 实时基于"你刚才在听什么"生成的"具体的没有发现"，才让用户相信这是真实运转的世界。
② 历史依赖 第 2 幕用"侧耳"听到的内容，应该让第 3 幕用"细看"看到的细节读起来不一样。累积的叙事厚度只能由 AI 实时整合上下文生成。预写做不到——你不可能为前 K 幕的所有可能解锁路径组合都写一个匹配版本。
③ 身份的真实位置 不同身份的视角、信息权限、认知边界完全不同。茶馆掌柜不会用鉴查院黑话；鉴查院文书不会"听不懂内库一词"。每个身份都要重写——AI 通过身份上下文 prompt 自然处理这一切。
④ 可扩展性 这个产品的真正价值是框架可复用到腾讯视频整个 IP 库。如果每一部剧、每一个事件、每一个工具点都需要人工撰写，扩展成本会让商业模式不成立。
结论

离开 AI，《庆余年 · 水下》不是"会变得更差"，而是"不可能存在"。

更准确地说——离开 AI，这个产品形态的整个商业价值（覆盖腾讯视频整个 IP 库的可复用衍生层）也不可能存在。AI 既是这个产品的体验内核，也是它的商业模式支柱。

3.4 技术方案

系统架构

整个产品采用 Next.js + Vercel 全栈一体化架构，无需独立后端。模型层采用 OpenAI 兼容协议——可在不改业务代码的前提下切换底层模型，给后续接入腾讯混元等自有模型留出空间。

分层 Prompt 架构

这是这个产品 AI 能力的核心。System prompt 采用六层结构，让"框架"和"IP 内容"彻底解耦——换一个 IP，只需要替换 Layer 1–3，Layer 4–6 完全复用。

SYSTEM PROMPT · 6 LAYERSFRAMEWORK ↔ IP DECOUPLED
L1 · WORLD
世界观 brief（约 300 字）  |  IP 包
L2 · CHARS
8 个核心角色档案：性格 / 动机 / 关系  |  IP 包
L3 · ROLE
用户身份上下文：位置 / 权限 / 认知边界  |  IP 包
L4 · TOOL
当前工具的语义边界（4 选 1）  |  框架
L5 · IO
输出协议（严格 JSON schema）  |  框架
L6 · RULE
纵深生成规则（8 条硬约束）  |  框架

关键设计约束

约束设计目的
默认 hasDepth=false防止 AI 为了"显得聪明"硬挖信息，保护"发现"的重量感
身份权限边界小人物不允许出现上帝视角（茶馆掌柜不应"知道庆帝的真实想法"）
JSON + 双重解析 fallback兼容模型偶发输出 markdown 代码块、多余文本，确保前端永不崩
主线只读AI 不允许编造原作中不存在的角色或事件，不允许改写已发生的剧情
工具语义匹配不让"侧耳"返回视觉信息，不让"追忆"返回当下事件——让每个工具的语义清晰

4.3 接入腾讯视频站内的具体路径

我们设想的接入方式不是另起一个独立 App，而是深度嵌入腾讯视频现有产品体系。具体有四个落点：

CHANNEL 01 · 剧集播放页
底部入口直推

剧集每集播完时，在播放页底部推送「进入庆余年 · 水下」入口。配合算法判断——刚刷完关键剧情节点的用户更可能愿意继续探索。承接"看完一集还不想走"的最直接路径。

CHANNEL 02 · 会员特权
VIP 增值能力

水下体验作为 VIP 会员的增值特权——非会员能看主线但不能解锁纵深，会员可以无限解锁。直接强化付费动机，并和现有会员体系打通。

CHANNEL 03 · IP 专题 Tab
独立 Tab 模块

每个头部 IP 在站内有独立的内容聚合 Tab（已有形态），把"水下"作为这个 Tab 里的一个核心模块。剧荒期用户回到 IP 专题，水下提供持续的内容供给。

CHANNEL 04 · 分享卡片
站外回流入口

每个用户结束体验后生成的分享卡片，带腾讯视频水印 + 二维码，分享到微信/朋友圈/小红书后可以直接回到腾讯视频。把"站外讨论"路径反向切回站内的关键机制。

4.6 商业化思考

商业价值的来源 · 直接呼应模块一的双向痛点

这个产品的所有商业价值，都可以从"补齐结构性缺口"的角度来理解：

VALUE 01 · LIFETIME
延长 IP 生命周期

衍生层让 IP 在剧播完后持续产生消费 — 单 IP 的活跃消费窗口从"播出期"延展到"长尾期"。

VALUE 02 · ENGAGEMENT
拉高用户停留时长

剧播完后用户不跳出 App，继续完成一段水下体验 — 直接增加广告库存与会员价值。

VALUE 03 · RETENTION
降低剧荒期会员流失

剧荒期用户能回到喜欢的世界观继续消费 — 改善 ARPU 与续费率。

VALUE 04 · ACQUISITION
社交传播带动新用户

分享卡片成为 IP 出圈载体，反向把新用户带回主内容 — 新增"内容反向引流"获客通道。

VALUE 05 · IP ROI
IP 资产价值放大

衍生层成为 IP 投资 ROI 的新组成部分 — 提升头部内容采购的可承受成本上限。

VALUE 06 · MEMBERSHIP
会员特权差异化

水下作为 VIP 增值能力 — 强化付费动机，与现有会员体系打通。

商业模式

短期作为腾讯视频会员的增值能力——最低摩擦的路径，不需要让用户付额外费用，但显著提升会员价值感知。中期可演进出几种独立商业模式：

模式说明
单 IP 永久解锁用户为某部喜欢的剧的衍生层付费一次（类似 IAP）
特殊身份解锁基础身份免费 + 进阶身份付费（如"扮演剧中没有出现过的特殊角色"）
IP 联动运营与影视宣发结合，新剧开播时同步推出衍生层，作为内容营销的一部分
官方授权变现原作版权方与平台共同分成 — 对腾讯视频自制 IP 尤其顺畅

不做的边界

商业化必须有边界，否则这个产品的"长期信任资产"会被消耗。我们明确三件事不做：

边界原因
① 不消解原作的作者性AI 不允许改写主线、不编造关键事件、不让"已经死的角色活下来"。这是产品被腾讯视频用作官方衍生层的前提。
② 不做信息茧房每一次发现都基于"当前场景客观存在的触发物"，而不是用户的口味画像。强调的是"看到不同视角"，不是"看到更多你喜欢的视角"。
③ 不替代原作消费所有设计都默认用户先看了原作。结语和分享卡片不会泄露用户尚未看到的剧情。水下是放大器，不是替代品。

EPILOGUE · 结语

长视频该被怎样改造

赛题问的是 AI 原生时代"看内容"这件事的终极形态。

我们注意到，这个时代有几种试图回答这个问题的方向。有人想把长视频做得更短、更刺激（解说视频、AI 切片）；有人想把长视频做成游戏（让观众做选择、改变结局）；有人想让用户当编剧（写 prompt 生成新剧情）。每一种都有它的合理性，但每一种都在用别的内容形态替代长视频本身。

我们的判断是另一个方向——长视频在所有内容形态里真正不可替代的，是叙事的纵深和角色情感的厚度。这是抖音做不到的，是 Character.AI 做不到的，是任何短视频或交互游戏做不到的。

AI 进入长视频，不应该削平这种纵深，让长视频变得更像别的；AI 应该放大这种纵深，让长视频成为它本来就该成为的样子——一个观众可以"住进去"的世界。

观众想要的从来不是"我来决定接下来发生什么"。观众想要的是"我还想再多看看这个世界，看看那些镜头没拍到的地方"。

《庆余年 · 水下》是我们对这个问题的回答

它不试图改造"看视频"这件事本身。它在剧播完之后开辟了一个新的入口——你看完了水面上的故事，现在可以进来，从一个角落里的小人物的眼睛，看到水面之下那座完整的冰山。

每一部剧
都是一座冰山。
你看到的，
只是水面以上。
