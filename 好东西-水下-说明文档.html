ONE JUDGEMENT / SECOND-LAYER WORLD

目录与 30 秒摘要

P.02

剧播完后，用户的延展兴趣（搜解析、补考据、找名场面、对照角色心思）几乎全部流向站外。腾讯视频承担核心内容投入且拥有官方资源，却缺少一个承接剧后内容消费的站内产品形态。

《腾讯视频·水下模式》补的就是这一层：当用户想更深入理解一部剧、想知道同一个饭桌上每个人当下在想什么时，可以在腾讯视频内继续走进这个故事。主线剧情不被改写，但观看视角可以改变。

它不是聊天工具，也不是互动小说，而是一套可复用的长视频衍生 AI 交互框架：AI 基于官方资源与当前语境判断“此刻能否看见更深一层”，为每次探索生成不可预写、但仍然还原且深刻的内容。

00 · One Judgement
00
NARRATIVE DEPTH / PRODUCT THESIS

一个判断

P.03

赛题问的是：AI 原生时代“看内容”这件事的终极形态。我们的判断是——AI 给长视频带来的不是“更多自由度”，而是“更多纵深”。

每一场戏都是一张桌子。观众看到的是桌面以上：剧本写好的台词、镜头拍下的画面、剪辑保留的镜头。桌面之下还有一整层：每个人此刻没说出口的话、心里正在算的账、上一次同样的话被谁讲过、桌下偷偷握起又松开的手。

AI 不改变一部剧讲了什么。AI 让观众有能力往水下看。

基于这个判断，我们做了《腾讯视频·水下模式》：一个腾讯视频长视频 IP 的 AI 衍生交互层。看完一集后，用户可以用片中任意一个角色的位置“再活”一遍那场饭桌。固定的是世界，主线由原作锁定；自由的是眼睛，用户选择从谁的位置看。

核心准则

RULE 01

同一帧画面，换一个人看会变厚

视角不是装饰性人物卡，而是信息权限。小叶能看见自己的勇气，铁梅能看见自己的克制，茉莉能看见大人没有说出口的东西。

RULE 02

不是改剧情，是换位置

用户不能决定谁泼水、谁离开、谁说台词。交互只发生在“往哪里看得更深”，不发生在“接下来发生什么”。

产品边界

它不是宣传语，而是严格的产品边界：主线只读、视角有权限、AI 默认克制。这个边界决定了它和互动影游、AI 角色聊天、用户写 prompt 生成新剧情的根本不同。

01 · User Insight
01
USER VALUE / PLATFORM GAP

用户洞察与问题定义

P.04

《腾讯视频·水下模式》解决的不是“让视频更好玩”这一层表面问题，而是长视频剧后消费被站外平台承接走的结构性缺口。

目标用户

用户类型典型行为当前缺口产品机会
分享型年轻观众追剧时发截图、金句、人物 cut分享素材多来自站外，腾讯视频只承担播放入口用个性化结语和分享卡，把“我从谁的位置看到的”变成可传播微叙事
深度 IP 粉丝看解析、补设定、复看名场面深度消费发生在豆瓣、B 站、小红书等站外社区用 AI 生成镜头之外的纵深，让站内承接“看懂更多”的需求
剧荒回访用户回到喜欢的老 IP 重刷片段或搜二创回访路径零散，缺少新的官方体验入口用多视角和关键场，让老 IP 在剧荒期仍有新的消费理由

排除三个错误方向

NOT 01

分支选择叙事

把看剧变成做题。频繁选择会把用户从观看者变成路径判断者。

NOT 02

让用户写 prompt

大多数观众不想当编剧。写 prompt 是创作，不是消费。

NOT 03

把长视频变成别的形态

解说、游戏化、开放世界都在替代长视频本身，而不是放大长视频。

三个使用场景

SCENE 01
意犹未尽：用户刚看完《好东西》第二次饭桌，播放页底部出现“进入腾讯视频·水下模式”。原本属于豆瓣/小红书的剧后消费，留在腾讯视频。
SCENE 02
剧荒回访：用户没新剧追，但想起来水下里还没玩过茉莉视角的那场戏。衍生层让 IP 在剧荒期依然能产生消费。
SCENE 03
反向激活：朋友圈出现分享卡“我是铁梅，那一桌饭我没说话，但我看见了小叶为什么泼那杯水”。分享卡把站外讨论反向带回腾讯视频。

01 · Problem Definition
01
DOUBLE-SIDED PAIN POINT

同一件事的两面

P.05
USER SIDE

用户侧：剧播完，关系结束

一部真正打动人的剧会在观众脑子里继续运转：继续猜想、回味、怀念、想要二刷。但当下产品形态是剧播完，App 关掉，关系结束。

PLATFORM SIDE

平台侧：长尾资产沉淀在别处

剧播完后，讨论热度、二创流量、剧粉社区、考据生态，这些围绕 IP 的社交资产往往沉淀在豆瓣、小红书、微博和 B 站。

核心洞察

洞察用户现象产品机会
看完不等于消费结束用户看完正片继续搜解析、看二创、补设定剧后消费应该被腾讯视频站内承接
用户想探索，不想改写观众想“再多看看这场戏”，不是决定剧情走向交互应从改写剧情转向探索纵深
IP 长尾正在外溢讨论、二创、复看主要沉淀在站外平台腾讯视频需要官方、个性化、可分享的 IP 衍生层
立论

《腾讯视频·水下模式》就是为这一块缺失而设计的。它把剧后消费从“去站外寻找解释和余韵”，改成“在腾讯视频里继续走进这个故事”。

02 · Product Design
02
PRODUCT MECHANISM / VIEWPOINT FIRST

产品方案设计

P.06

《腾讯视频·水下模式》可以理解为腾讯视频正片之后的官方剧后体验入口。用户看完剧、还想继续理解人物和事件时，不需要跳去站外搜解析，而是直接进入一个由原作场景搭建的互动空间。

产品边界

边界含义
主线固定谁泼了那杯水、铁梅最后说了什么，由原作决定，用户不能改写。
体验像看剧，不像做题大多数时候系统自动播放剧情，用户只在“这里还能不能看深一点”时主动使用 AI 交互。
选择改变视角用户选择的不是“接下来发生什么”，而是“我站在谁的位置看这件事”。

机制一 · 同桌视角选择

视角在桌上的位置这一桌饭意味着什么
小叶小马的朋友、铁梅的好朋友替朋友抱不平的勇气、对“恋爱脑”标签的反抗
王铁梅这一桌饭的主人维持桌面平衡的克制、对小叶选择的复杂情绪
茉莉铁梅的女儿被大人忽略但什么都看见的眼睛
小马前男友自我合理化、被动应付、试图维持体面
前夫旁观局外人嘲讽混杂着尴尬，看得见但不参与

机制二 · 视觉小说式主线播放

[镜头 / 旁白] -> [角色对话 x N] -> [你的感知] -> (可选) [水下回响]

关键设计：当用户在某一帧停下来想看深一点时，AI 调用以“这一帧的当前 beat 文本”为锚，不是整段大模糊。这样水下内容始终贴着具体台词、动作或物件生长。

02 · Product Mechanisms
02
TOOLS / ECHO / PERSONAL ENDING

三工具与水下回响

P.07

机制三 · 三个工具：AI 自主判断纵深

OBSERVE

观察

视觉纵深。看见物件、表情、动作里的信号：桌上那杯水、对面那个人此刻的眼睛、谁在偷偷看谁。

MEMORY

回忆

时间纵深。这一刻让“我”想起了什么：同样的话、同样的场面、上一次发生的时候我做了什么。

ARCHIVE

翻看

知识纵深。翻看世界里的资料、记录、过往。在《好东西》的语境里更克制，多用于跨集呼应。

关键设计：默认是“没有发现”

同一个工具在不同视角、不同帧上可能有发现，也可能什么都没有。我们刻意让“没有发现”成为正常结果。这样每一次真的看见水下，才会有分量；同时也能守住每个视角的可信边界，避免 AI 把用户变成上帝视角。

机制四 · 水下回响

用户前面发现的内容不会看完就消失。系统记录到 depthHistory，并在下一帧 / 下一幕以“水下回响”的方式回到主线里。

例如小叶视角第五幕，AI 把前一次回忆中她下的决定“下次再被这样讲，我要替自己说话”作为水下回响，回到这一帧“我很不喜欢这个词”的旁边。同一句话被读出了重量。

机制五 · 结语生成与分享卡片

一条视角线结束后，系统根据用户走过的所有 beat 和所有水下，生成一段个人结语、一张分享卡片和一组旅程回看。用户带走的不是通用成就页，而是“我从谁的位置看了那一桌饭”。

02 · Demo Flow

REAL DEMO / SIX TOOL CALLS

一条实际玩法

P.08

跟着小叶看完那一桌饭，再换铁梅看一遍。完整流程包含 6 次工具调用、1 次视角硬切、3 次水下回响。

小叶视角

节点工具锚点水下输出
第四幕 · 泼水之后观察“铁梅你看。”小叶不是泼给小马的，是泼给铁梅看的。她在用这一下提醒铁梅：你也可以不让。
第五幕 · “恋爱脑”回忆“我很不喜欢这个词。”上一次有人这样讲她，她没顶嘴。她下了决定：下次再被这样讲，我要替自己说话。
第五幕 · 反命名回忆“更勇敢更有爱的能力。”第一次给自己的爱重新命名。水下回响第一次出现：[袒露 -> 命名]。
第五幕 · 算账回忆“不爱我会更苦。”她真的算过的账。水下回响：[袒露 -> 命名 -> 实证]，小叶线收束。

跨视角硬切

用 url query ?id=tiemei&scene=3 直接跳回第四幕同一帧，视角徽标从小叶翻成铁梅，色温从微暖转向偏冷。

节点工具锚点水下输出
第四幕 · 同一帧观察“铁梅你看。”暖黄餐灯落在小马身上，小叶端杯子那一秒她的眼睛是笑着的。铁梅当下就懂了：这是小叶在替她出手。
第五幕 · 终回响观察“我只是不想你受伤。”铁梅胃缩了一下。她选了不爱、不苦、也不勇敢的那条路。终回响：呼应小叶的“不爱会更苦”。
我从小叶的位置坐了一桌饭，又从铁梅的位置坐了一遍：同一杯水、不同的目光、两个人各自的账。

03 · AI Native
03
AI AS EXPERIENCE CORE

AI 原生能力说明

P.09

AI 在这个产品里不是装饰，不是宣传词，不是在已有产品上叠加的“智能小工具”。这个产品离开 AI 不可能存在。

五项 AI 核心能力

#能力含义
01跨域叙事结构理解整合世界观规则、角色档案、用户视角、当前帧 beat、历史发现和当前工具语义。
02纵深存在性判断 hasDepth默认不生成内容。AI 必须先回答：当前视角 × 当前帧 × 当前工具，是否存在自然、合理、不越权的水下信息。
03上下文敏感的纵深生成当 hasDepth=true 时，AI 生成的是用户可以直接体验的纵深内容，不是抽象解析。
04纵深内容的叙事化组织判断内容应通过环境、角色心声、沉默或点到为止的方式浮出。
05个性化结语与分享素材组织每条视角线结束后合成结语和分享文案，让分享卡本身成为可传播的微叙事。

hasDepth 的三个允许条件

CHECK 01

触发物存在

当前帧 beat 文本中存在明确触发物，一句台词、一个动作、一件物件，而不是 AI 凭空想象。

CHECK 02

工具语义匹配

观察触达视觉细节，回忆触达时间线索，翻看触达资料或跨集信息。

CHECK 03

视角权限合理

用户的角色视角有立场看见这个信息。小叶不应知道铁梅此刻心里在算什么。

03 · Why AI
03
IMPOSSIBLE WITHOUT AI

离开 AI 还能成立吗？

P.11

假设不用 AI，预先写完所有内容。结论不是“体验会变差”，而是产品形态本身会不成立。

枚举维度组合数问题
单部剧 / 单集 / 工具点5 视角 × 5 幕 × 3 工具 ≈ 75看似可控
叠加历史路径依赖75 × K每个工具点要写多个版本
单 IP 多集每一集都要重复一轮工作量线性膨胀
更多 IP 接入× IP 数 × 平均集数人工穷举不可维护

即使写完，体验依然失败

LOSS 01

自然空结果

大部分工具点回应“没有发现”。固定字符串用一两次就会被识破。AI 实时基于上下文生成的具体空结果，才让用户相信世界在运转。

LOSS 02

历史依赖

第三幕用回忆听到的内容，应让第四幕观察读起来不一样。累积的叙事厚度只能由 AI 实时整合上下文生成。

LOSS 03

视角的真实位置

不同视角的认知边界、说话方式、能看见的细节完全不同。AI 通过视角上下文 prompt 自然处理这一切。

LOSS 04

可扩展性

如果每一部剧都需要人工撰写，扩展成本会让商业模式不成立。AI 既是体验内核，也是商业模式支柱。

FRAMEWORK / PRODUCTION PIPELINE

落地与商业化

P.12

我们做的不是一个孤立 demo，而是一套“框架 + IP 内容包”的站内剧后体验能力。框架一次性建设，内容包随 IP 替换。

框架与内容包

FRAMEWORK

一次性建设

  • 视觉小说式播放引擎
  • 主线锁定 + AI 打光协议
  • 三个工具的语义体系
  • 分层 Prompt + JSON 解析容错
  • 水下回响累积机制
  • 结语 + 分享卡片合成
IP PACKAGE

每个 IP 替换一次

  • 世界观 brief
  • 核心角色档案
  • 用户视角设定
  • 固定主线节点
  • 视觉素材包
  • 工具命名与语气规则

五步生产流水线

STEP 01
输入 INPUT：剧本 / 角色小传 / 分集大纲 / 正片关键帧 / 官方物料进入资料库。站外平台拿不到这些原始素材。
STEP 02
分析 ANALYZE：AI 提取叙事结构网，包括人物关系、关键事件、未展开支线、情绪节点和世界规则。
STEP 03
提取 EXTRACT：析出角色沉默、事件余波、小人物视角、被剪掉的关系线。每张水下卡都有水面锚点。
STEP 04
生成 GENERATE：组装成可运营的 IP 内容包：观察位、水下节点、触发物、工具建议、回响规则。
STEP 05
审核 · 上线 REVIEW：经过边界、剧透、OOC、官方口径四道审核闸门后，进入腾讯视频站内运营。

P.13

接入腾讯视频站内的具体路径

CLOSING STATEMENT

长视频该被怎样改造

P.14

AI 进入长视频，不应该削平这种纵深，让长视频变得更像别的；AI 应该放大这种纵深，让长视频成为它本来就该成为的样子：一个观众可以“住进去”的世界。

这个时代有几种试图回答“AI 原生时代看内容”的方向：把长视频做得更短、更刺激；把长视频做成游戏，让观众做选择、改变结局；让用户当编剧，写 prompt 生成新剧情。每一种都有合理性，但每一种都在用别的内容形态替代长视频本身。

我们的判断是另一个方向：长视频在所有内容形态里真正不可替代的，是叙事的纵深和角色情感的厚度。这是短视频做不到的，是 AI 角色聊天做不到的，是任何交互游戏都做不到的。

观众想要的从来不是“我来决定接下来发生什么”。观众想要的是“我还想再多看看这一桌饭，看看那些镜头没拍到的地方”。

《腾讯视频·水下模式》是我们对这个问题的回答。它不试图改造“看视频”这件事本身。它在剧播完之后开辟了一个新的入口：你看完了桌面上的故事，现在可以进来，从任意一个人的位置，看到桌面之下那一整层。
