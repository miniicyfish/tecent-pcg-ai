# 原型设计工作流与 UI 准则

> 用途：约束《水下模式》复赛产品原型的页面设计质量。  
> 使用方式：每次 subagent 生成或修改 HTML 产品原型前，必须先阅读本文档，并按自检清单执行。

更新时间：2026-05-24

## 1. 总原则

### 1.1 一页只服务一个主任务

每个页面只回答一个核心问题。

例如：

- 播放结束入口：用户看完后，为什么要进入水下模式？
- 本集探索图谱：这一集有哪些片刻可以再看一层？
- 视角选择页：这段事件可以从哪里进入？
- 水下体验页：从当前视角重新观看这一幕。
- 水下回看页：这次我看见了什么，如何带走或分享？

如果一个页面同时承担太多任务，它会变成产品说明页，而不是真实用户 UI。

### 1.2 第一屏只保留一个主视觉和一个主动作

首屏需要让用户 5 秒内理解：

- 我在哪里？
- 我刚刚完成了什么 / 即将做什么？
- 我现在最自然的下一步是什么？

不要在首屏同时展示多个同等权重模块。功能可以存在，但应通过层级逐步展开。

### 1.3 功能用层级展示，不要平铺

复杂信息应该渐进呈现。

可使用：

- tabs：回看 / 对照 / 卡册 / 邀请。
- 横向卡组：水下卡册、事件片刻。
- 折叠区：更多视角、更多发现。
- 侧栏轻入口：邀请朋友、收进档案馆。
- hover / tooltip：补充解释，而不是把解释直接铺在页面上。

不要把所有功能、所有解释、所有按钮一次性摊在一个屏幕里。

### 1.4 UI 不解释产品理念

产品理念是给评委讲的，不是写给用户看的。

用户页面不要出现：

- “信息边界选择器”
- “非 AI 玩法”
- “多人补完”
- “避免普通互动游戏”
- “AI 原生能力”
- “叙事纵深机制”
- “本页面的作用是……”

这些可以出现在视频口播、讲解文档或生产流程页，但不应该出现在真实产品 UI 里。

### 1.5 文案像内容产品，不像产品汇报

避免：

> 通过多视角对照，你可以理解同一事件的叙事纵深。

改成：

> 这一幕，从后台看，是另一种停顿。

避免：

> 用户可以通过好友视角拼图完成多人补完。

改成：

> 我从后台看见了这一幕，邀请你从另一个位置再看一次。

## 2. 水下模式专属设计边界

### 2.1 不做游戏结算页

水下模式不是闯关游戏。

避免：

- 积分。
- 排名。
- 通关。
- 成就。
- 大量进度百分比。
- “你获得了 XX 卡”这种强游戏语气。

可以使用：

- 回看。
- 收藏。
- 水下卡。
- 片刻。
- 继续看另一个视角。
- 收进档案馆。

### 2.2 不做路演说明图

真实用户页面不应该像给评委看的功能示意图。

避免在 UI 里写：

- 1 选事件 / 2 选视角 / 3 进入水下。
- 产品价值说明。
- AI 工作原理说明。
- “腾讯视频可以通过该功能承接剧后消费”。

这些内容应该放在视频口播或专门的 AI 生产流程页里。

### 2.3 不做角色档案页

视角选择不是角色档案，也不是角色抽卡。

观察位卡片应轻量、可扫读：

- 头像。
- 视角名。
- 位置短句。
- 一句视角差异。
- 2-3 个标签。
- 状态。
- CTA。

不要每张卡写大段人物设定。

### 2.4 不把信息边界说得太直白

不要写：

- 能看见……
- 看不见……
- 信息权限……

更适合：

- 用位置暗示边界。
- 用短标签暗示靠近的内容。
- 用一句自然文案表达视角差异。

例如：

> 后台 · 调音台旁  
> 最靠近手机停顿和乐队玩笑

而不是：

> 能看见小叶手机停顿和乐队玩笑，看不见她和胡医生完整私密关系。

## 3. 页面设计流程

每次设计一个页面前，先回答以下问题。

### 3.1 页面主任务

这页只服务哪一个主任务？

如果一句话说不清，说明页面任务太多，需要拆分。

### 3.2 第一眼

用户打开这页 5 秒内应该看到什么？

只能选一个主视觉和一个主动作。

### 3.3 信息层级

哪些信息必须在第一屏？

哪些信息可以放到：

- tab 里。
- 折叠区里。
- 横向滚动卡组里。
- 次级页面里。
- 视频口播里。

### 3.4 用户语言

页面上的每句话是不是用户能自然理解的语言？

如果一句话更像产品经理、评委讲解、技术方案，就删掉或换成内容语言。

### 3.5 真实产品感

这页像不像用户真的会在腾讯视频里看到的页面？

如果更像路演 PPT、功能说明图、游戏面板或 dashboard，需要重做层级。

## 4. 常用页面模式

### 4.1 播放结束入口

主任务：

> 在播放结束后，用一个轻量入口承接用户的剧后余韵。

设计要点：

- 像真实播放结束页。
- 水下入口作为剧后推荐出现。
- 不要放产品流程说明。
- 不要像广告弹窗。

### 4.2 本集探索图谱

主任务：

> 把刚看完的一集转化为可探索的事件结构。

设计要点：

- 事件优先。
- 人物作为筛选，不是唯一入口。
- 不叫地图，避免游戏化。
- 使用“图谱”“本集水下”“本集探索”等内容产品语言。

### 4.3 视角选择页

主任务：

> 在一个具体事件下，选择从哪里进入。

设计要点：

- 像选择观看角度，不像选职业。
- 卡片轻量，不写角色小作文。
- 用位置、标签、短句暗示视角差异。

### 4.4 水下体验页

主任务：

> 从当前视角重新观看这一幕。

设计要点：

- 像片段再观看，不像文字游戏。
- 工具是“看深一点”的自然动作，不是技能栏。
- 水下浮起像补充镜头，不像 AI 回复框。
- 少解释，多呈现。

### 4.5 本集水下回看页

主任务：

> 展示这次从某个视角看见了什么，并让用户带走。

设计要点：

- 第一屏只突出一句分享文案 / 一个主视觉。
- 视角对照、卡册、邀请朋友用 tab 或次级层级承载。
- 不要把所有玩法都铺在一屏。
- 像内容资产页，不像结算页。

## 5. Subagent 执行自检清单

每次交付原型前，subagent 必须检查：

- [ ] 这页是否只有一个主任务？
- [ ] 首屏是否只有一个主视觉和一个主动作？
- [ ] 是否有超过 3 个同权重模块同时抢注意力？
- [ ] 是否有大段解释性文案？
- [ ] 是否把内部设计理念写给用户看？
- [ ] 是否像真实用户 UI，而不是路演说明图？
- [ ] 是否有游戏化结算、积分、成就或任务感？
- [ ] 是否能 5 秒看懂这页要做什么？
- [ ] 页面文案是否更像内容产品，而不是产品汇报？
- [ ] 次要功能是否通过 tab、折叠、横滑、侧栏等方式渐进展示？

如果任意一项不通过，先修改页面层级，再交付。
